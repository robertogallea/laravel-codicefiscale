# The Faker provider bundles ten well-known municipality facts directly in code; ADR-0003 still governs the real BirthPlace dataset

ADR-0003 says the package ships no committed snapshot of ANPR/MAECI data, because bundling a *converted copy of a government dataset with unclear redistribution terms* would redistribute it under the package's own unverified authority. `CodiceFiscaleProvider` (ticket #88) needs a handful of real, currently-valid municipality cadastral codes to generate fake data without requiring `codice-fiscale:update-places` to have ever run - so it hardcodes ten major cities' current code/province/ISTAT-code/validity-start as PHP literals in `CodiceFiscaleProvider::knownBirthPlaces()`.

This is not the case ADR-0003 addresses. ADR-0003's risk is specific to *converting and redistributing the ANPR/MAECI data products themselves* - tables whose redistribution terms nobody has verified. A handful of independently-known, publicly-documented facts (e.g. "Roma's cadastral code is H501") carry no such licensing ambiguity; the same facts already appear as literals throughout this codebase's own test suite, sourced the same way. Bundling ten such facts to make one Faker method work offline is a different kind of act than bundling a converted archive, even though both involve "birthplace data" in the loose sense.

**The line stays narrow on purpose**: this ADR authorizes a small, explicitly-enumerated, hand-picked list of well-known facts for the Faker provider's specific purpose only - not a general exception to ADR-0003. Any future move toward a larger or programmatically-derived bundled list must be reasoned about under ADR-0003's original constraint, not this one.

**Considered options**: Require the Faker provider to depend on the real `BirthPlaceRepository` (rejected - reintroduces the exact "must run `update-places` first" dependency the ticket exists to avoid, for a feature whose whole point is working in a fresh app). Bundle nothing and let callers supply their own birthplace code (rejected - defeats the purpose of a zero-config Faker provider; user story 44 asks for realistic data with no hand-rolling).
