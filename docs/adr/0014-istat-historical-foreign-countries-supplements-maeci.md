# ISTAT's historical foreign-countries report supplements MAECI as a second foreign source

MAECI's stati-esteri table lists only currently existing countries and leaves `CODAT` empty for many current territories, so 3.x lost 75 of 2.3.1's 283 foreign codes (#122, #123). ISTAT's Situas report 469 "Storico Paesi esteri" (`reportspooljson?pfun=469&pdata=01/01/1990`) carries the cadastral code (`COD_AT`, from Agenzia delle Entrate) and ISO alpha-3 for current territories (Gibilterra `Z113`, Groenlandia `Z402`…) **and** for ceased states (`Stato storico`: `Z135` USSR, `Z118` Jugoslavia…). `codice-fiscale:update-places` downloads it alongside MAECI, and ISTAT fills the codes MAECI lacks; it supplements MAECI rather than replacing it.

## The merge rule

When both sources carry a code, **MAECI wins, unless ISTAT marks the code historical** (`TIPO_PAESE` `Stato storico` or `Territorio storico`), in which case ISTAT wins. A code ISTAT keeps as historical but MAECI lists under another entity is one the registry has **reassigned** to a successor, while the tax authority, which assigns codici fiscali, still uses it with its historical meaning. The case today is `Z501`: the Antille olandesi held it, Aruba included until 1 January 1986. ANPR/MAECI reused it for Aruba, while the fiscal systems kept "Antille olandesi", the name 2.3.1 used too. So `Z501` is "Antille olandesi" with `ANT`, the former ISO code of the ceased entity (ADR-0013, rule 2). Every other code both sources carry keeps MAECI's name and ISO code, so the import changes no row MAECI already supplied other than `Z501`.

Rejected: **splitting `Z501` into dated eras** (Antille olandesi before a date, Aruba after). No date is right. A cut at 1986 names people born in Curaçao or Sint Maarten up to the 2010 dissolution "Aruba", and a cut at 2010 is wrong for people born in Aruba between 1986 and 2010. The tax authority never moved Aruba off `Z501` in the first place, and curated foreign dates are rejected below anyway. **MAECI always wins**: simpler, but labels every `Z501` codice fiscale with a name the tax authority doesn't use. **ISTAT always wins**: it renames every row MAECI already supplies, a far larger change than one reassigned code warrants. People born in Aruba resolve to "Antille olandesi"/`ANT`, which is what their codice fiscale denotes, and a name search for "Aruba" doesn't find `Z501`.

ISTAT keeps a state after it ceases while MAECI drops it, so a future dissolution stays resolvable with no new bundled entry. Because ISTAT now carries the six ceased states in #122's group A, ADR-0012's admission rule keeps them out of the bundled list.

## Consequences

- **Licence**: like ANPR and MAECI, ISTAT data is downloaded by each installation (ADR-0003) and never redistributed by the package, so its CC BY 4.0 terms and the third-party origin of `COD_AT` raise no redistribution question.
- **Eras**: ISTAT, like MAECI, gives no per-row validity dates, and neither does the fixed list (ADR-0012). Every foreign era is therefore maximally wide, including ceased states and retired codes, so under ADR-0011 a foreign code is always attributable. Curated dissolution dates were rejected: none are published for the tax authority's practice (was `Z118` used until 1992 or 2003? when did Georgia move from `Z136` to `Z254`?), and a wrong date would falsely reject real codici fiscali. 2.3.1 never checked dates for foreign codes either.
- **Names** come from the source: `Z118` is "Jugoslavia" per ISTAT, regardless of 2.3.1's two conflicting names.
